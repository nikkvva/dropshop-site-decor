# dropshop-site — сайт-заготовка (CLAUDE.md)

Часть общего проекта `dropshop` (папка выше, свой репозиторий): там общая картина, единый план задач (`../CLAUDE.md`, здесь планов нет), ТЗ сайтов (`../docs/sites-plan.md`) и правила для всех частей.

## Окружение
- Docker, как в `dropshop-core`: все команды php, artisan, composer — через `docker compose exec app ...` из этой папки.
- `vendor/` живёт в томе Docker, на диске его нет. Код библиотек смотреть внутри контейнера.
- Админка: http://localhost:8081/admin · БД снаружи: localhost:3308. Порты — `APP_PORT`, `DB_PORT_EXTERNAL` в `.env` (у каждого сайта на одном ПК свои).
- `APP_LOCALE=uk`: сайт открытый, всё для клиента — на украинском (переводы Laravel — пакет `laravel-lang`, папка `lang/uk`).

## Что уже есть
- Ниша сайта: тексты главной и каталога, SEO — только в `config/niche.php` (название — `APP_NAME`). В шаблоны тексты ниши не писать: сайты делаются копией заготовки и получают её исправления через `git pull upstream`.
- Пустой Laravel 13 + Filament 5, вход в админку со строгим лимитом (`app/Filament/Auth/Login.php`, тест `tests/Feature/AdminLoginTest.php`).
- Класс входа лежит вне `app/Filament/Pages`, потому что эта папка сканируется автоматически.
- Товары: `php artisan products:sync` раз в час (контейнер `scheduler`) копирует товары категории `CORE_CATEGORY_ID` из dropshop-core в таблицу `products`. Пропавшие из категории не удаляются, а получают `is_available = false`. Пустой ответ dropshop-core — синк падает с ошибкой и ничего не меняет (иначе спрятал бы весь магазин). `slug` ставится только при создании товара: переименование у поставщика не ломает старые ссылки. Админка: раздел «Товары», только просмотр. Тест: `tests/Feature/SyncProductsTest.php`.
- Вёрстка: файлы шаблона Bazaro — `public/bazaro/` (css, js, шрифты, нужные картинки). Каркас `resources/views/layouts/app.blade.php`, куски — `partials/` (шапка, мобильное меню, подвал, карточка товара), главная — `home.blade.php` + `HomeController`. Наши правки стилей — `public/css/site.css` (файлы шаблона не трогаем). Тест: `tests/Feature/HomePageTest.php`.
- Каталог `/catalog` (`CatalogController`: в наличии, сортировка `?sort=`, по 24) и товар `/product/{slug}` (`ProductController`: товар не в наличии — плашка, не 404; «Інші варіанти» по `group_id`; «Схожі товари»). Описание поставщика выводится только через `Product::safeDescription()` (без опасных тегов и атрибутов). Характеристики приходят на русском — `Product::paramsUk()` переводит словарём `config/params_uk.php` (новые слова дописывать туда). SEO: свои `title`/`description`/`h1`, `canonical` и Open Graph в каркасе, JSON-LD Product, `/sitemap.xml`, `public/robots.txt`. Тесты: `CatalogPageTest`, `ProductPageTest`.
- Картинки сайта (логотип, иконка вкладки, 3 слайда × ПК/телефон, 2 баннера) меняются в админке: страница «Картинки сайта» (`app/Filament/Pages/SiteImages.php`, список мест — `IMAGES`). Пути хранятся в таблице `settings` (ключ → значение, `App\Models\Setting`), в вёрстке — `Setting::image('ключ', 'заглушка шаблона')`: не загрузили — показывается заглушка (серая, с размером 1400×660 и т.п.). Файлы — диск `uploads` = `public/uploads/` (не в Git, без `storage:link`), nginx не запускает оттуда PHP. Только JPG/PNG/WebP до 2 МБ (SVG нельзя: в нём бывает скрипт), иконка вкладки — только PNG. Заменили/убрали — старый файл удаляется. Новое место для картинки: ключ в `IMAGES` + `Setting::image()` в шаблоне. Тест: `SiteImagesTest`. Фото товаров — ссылки поставщика.
- Товары без фото: у поставщика новые товары часто приходят с пустым `<picture>` (~0,5% фида). На витрину (главная, каталог, «Схожі товари», sitemap) они не попадают — `Product::available()->withPhoto()`, новые списки товаров строить так же. По прямой ссылке и в корзине вместо фото — заглушка `public/images/no-photo.svg` (её отдаёт `Product::image()`). Фото появится у поставщика — синк подтянет, товар сам выйдет на витрину. Тест: `CatalogPageTest`.
- Зачёркнутую цену поставщика (`old_price`) не показываем: она есть у всех товаров (~+25% к цене), это не настоящая скидка. В базе хранится — пригодится для настоящих скидок (снижение цены между синками).
- Из шаблона убраны фейковые таймер акции, «продано за 16 часов» и логотипы карт (онлайн-оплаты нет) — не возвращать. Тексты про доставку/оплату/возврат — по условиям поставщика (`yavshoke.ua`, «Умови співпраці»).
- Связь с dropshop-core: `CORE_URL` (из Docker — `http://host.docker.internal:8080`), `CORE_API_KEY` (ключ из `SITE_API_KEYS` dropshop-core), `CORE_CATEGORY_ID` (демо: 343 «Смартфоны и аксессуары»).
- Параметры из адреса и формы, которые сравниваются как строка, читать через `$request->string('x', strict: true)`: боты шлют `?x[]=...`, и обычный `(string)` даёт 500.
- Пагинация (`partials/pagination.blade.php`): окно страниц через `$elements` + `onEachSide(1)`, на узком экране кнопки переносятся на вторую строку.
- Корзина `/cart` (`App\Services\Cart`): в сессии только `[id товара => количество]`, цены и наличие — из `products`. Товар, который закончился в корзине, — с плашкой, оформить нельзя. Кнопка «До кошика» — на странице товара и в карточке.
- Оформление `/checkout` (`CheckoutController`): заказ сохраняется у себя (`orders`, `order_items`), сразу уходит в dropshop-core (`App\Services\CoreOrderSender`, `external_id` = id заказа — повтор не создаёт дубль). Нет связи → покупатель всё равно видит «Дякуємо», заказ досылает `orders:resend` (каждые 10 минут, заказы не старше 2 дней) или кнопка в админке. dropshop-core ответил «нет в наличии» → заказ удаляется, товар снимается с продажи, покупатель возвращается в корзину.
- Оплата: при получении или передоплата на карту. Реквизиты — `SHOP_PAYMENT_DETAILS` в `.env` (показываются на «Дякуємо»; пусто — «менеджер надішле реквізити»). Онлайн-оплаты нет.
- Новая Почта (`App\Services\NovaPoshta`, `public/js/checkout.js`): подсказки города и пунктов. Отделения — весь список города, почтоматы — только поиск по номеру/улице (их тысячи, полный список Киева > 10 с). API ищет точный кусок текста, поэтому «перемоги 18» делится: в API — улица, дом фильтруем сами. Ключ `NOVA_POSHTA_API_KEY` необязателен: API отвечает и без него. Кэш ответов на сутки, в ключе версия `v2:` — поменял формат ответа, подними её.
- Проверки оформления: пункт только из подсказок — JS кладёт его `Ref` в `delivery_point_ref`, сервер сверяет с API (город и тип), название берёт из API, `Ref` хранится в `orders.delivery_point_ref` (в dropshop-core не уходит). API не отвечает — пункт принимается текстом, `Ref` пустой. Телефон приводится к `+380XXXXXXXXX` («050 123 45 67» тоже подходит). ПІБ — минимум 2 слова из букв (дефис и апостроф можно).
- Админка: раздел «Заказы» (только просмотр, красный счётчик — не дошедшие до dropshop-core, кнопка «Отправить в dropshop-core»). Тесты: `CartTest`, `CheckoutTest`, `NovaPoshtaTest`.

## Команды
- `php artisan test` — тесты
- `php artisan make:filament-user` — создать пользователя админки
- `php artisan orders:resend` — дослать в dropshop-core неотправленные заказы (то же делает планировщик)
